## La idea

Un <Term slug="worker-thread">worker thread</Term> es otro hilo con su **propio event loop y su propia instancia de V8**. Mientras calcula, el hilo principal sigue atendiendo peticiones.

```js title="main.js"
import { Worker } from 'node:worker_threads';

const worker = new Worker(new URL('./primes.worker.js', import.meta.url), {
  workerData: { limit: 5_000_000 },
});
worker.once('message', (count) => console.log(`${count} primos`));
worker.once('error', (error) => console.error(error));
```

```js title="primes.worker.js"
import { parentPort, workerData } from 'node:worker_threads';

let count = 0;
for (let n = 2; n < workerData.limit; n++) {
  let prime = true;
  for (let d = 2; d * d <= n; d++) if (n % d === 0) { prime = false; break; }
  if (prime) count++;
}
parentPort.postMessage(count);
```

## Comunicación

- Los datos que envías (`workerData`, `postMessage`) se **copian** con el algoritmo de clonado estructurado: funciona con objetos, arrays, `Map`, `Date`, Buffers… pero no con funciones ni clases con métodos.
- Copiar 100 MB tarda: para datos binarios grandes, **transfiérelos** (`postMessage(buffer, [buffer])`) y dejan de estar disponibles en el hilo origen.
- Para memoria realmente compartida existe `SharedArrayBuffer` con `Atomics`, pero rara vez lo necesitarás.

## ¿Cuándo usarlos?

<Columns>
  <Column title="Sí" tone="good">
    Cálculo intensivo: informes, compresión, procesado de imágenes, hash de muchos archivos, parseo de JSON enormes.
  </Column>
  <Column title="No" tone="bad">
    E/S: leer archivos, consultas, peticiones HTTP. Node ya las hace en segundo plano; un worker solo añade coste.
  </Column>
</Columns>

Crear un worker cuesta decenas de milisegundos y memoria. Si lanzas muchos, usa un **pool** que los reutiliza (la librería `piscina` es la referencia).

## Errores comunes

- Crear un worker por petición sin límite: cien peticiones simultáneas, cien hilos.
- Olvidar el evento `'error'`: una excepción en el worker no aparece en ningún sitio.
- Pasar funciones o instancias de clase en `workerData`: lanza `DataCloneError`.
