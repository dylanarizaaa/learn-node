## Tres formas de enterarse de los cambios

| Técnica | Cómo funciona | Úsala cuando |
| --- | --- | --- |
| Polling | El cliente pregunta cada N segundos | Los cambios son raros y la latencia da igual |
| <Term slug="sse">SSE</Term> | Una respuesta HTTP que no termina; el servidor escribe eventos | El servidor avisa al cliente (notificaciones, progreso, paneles) |
| <Term slug="websocket">WebSocket</Term> | Canal bidireccional persistente | Ambos lados envían a menudo (chat, juegos, edición colaborativa) |

## Server-Sent Events

Es HTTP normal con un formato de texto muy simple. Cada evento son líneas `campo: valor` terminadas por una línea en blanco:

```http
HTTP/1.1 200 OK
Content-Type: text/event-stream

: esto es un comentario (se usa como latido)

event: expense.created
data: {"id":7,"amount":1250}

```

En el navegador se consumen con `new EventSource(url)`, que además **reconecta solo** si se corta. En Node puedes leerlos con `fetch` y el `body` como stream.

## WebSockets

Empiezan como una petición HTTP con `Upgrade: websocket` y, a partir de ahí, la conexión transporta mensajes en los dos sentidos. Node incluye un **cliente** `WebSocket` global; para el **servidor**, la librería estándar es `ws`:

```js
import { WebSocketServer } from 'ws';

const wss = new WebSocketServer({ server }); // comparte el servidor HTTP
wss.on('connection', (socket) => {
  socket.on('message', (data) => {
    for (const client of wss.clients) client.send(data.toString()); // difunde a todos
  });
});
```

Lo verás completo en el proyecto [Chat en tiempo real](/docs/proyectos/chat-en-tiempo-real).

## Lo que no puedes olvidar

- **Limpiar al desconectar**: cada conexión añade listeners a tu bus de eventos. Si no los quitas en `'close'`, la memoria crece con cada cliente que pasó por ahí.
- **Latidos**: proxies y balanceadores cortan conexiones inactivas (a menudo a los 60 s). Envía un comentario o un *ping* cada 20–30 s.
- **Autorización por evento**: cada cliente debe recibir solo lo suyo.
- **Varias instancias**: un `EventEmitter` vive en un proceso. Con [cluster](/docs/avanzado/cluster) o varias máquinas necesitas un bus compartido (Redis pub/sub, PostgreSQL `LISTEN/NOTIFY`).
