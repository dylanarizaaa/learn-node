## Primero, lo que ya viene incluido

Node moderno trae de serie muchas cosas que hace unos años exigían instalar paquetes. Esta guía las usa siempre que basten:

| Necesidad | Incluido en Node | Antes se instalaba |
| --- | --- | --- |
| Reiniciar al guardar | `node --watch` | nodemon |
| Variables de entorno desde `.env` | `node --env-file=.env` | dotenv |
| Tests, mocks y cobertura | `node:test`, `node --test` | Jest, Mocha, nyc |
| Peticiones HTTP | `fetch` global | axios, node-fetch |
| Leer argumentos de la CLI | `util.parseArgs` | yargs, commander |
| Colores en la terminal | `util.styleText` | chalk |
| Base de datos local | `node:sqlite` | better-sqlite3 |
| Ejecutar TypeScript | *type stripping* | ts-node, tsx |
| Hash de contraseñas | `crypto.scrypt` | bcrypt |

## Alternativas que conviene conocer

- **Fastify**: framework HTTP más rápido que Express y con validación por esquemas integrada. Lo que aprendas de Express se traslada casi directo.
- **NestJS**: framework con arquitectura opinada (módulos, inyección de dependencias, decoradores). Útil en equipos grandes; aprende primero las bases.
- **Hono**: framework ligero basado en APIs web estándar que funciona en Node, Bun, Deno y entornos *edge*.
- **Prisma / Drizzle**: ORMs para PostgreSQL y otras bases de datos. Los verás en [PostgreSQL y ORMs](/docs/datos/postgresql-y-orms).
- **Bun y Deno**: otros runtimes de JavaScript, compatibles en gran parte con Node. Node sigue siendo la opción estándar en producción.

<Callout type="tip" title="Criterio de esta guía">
Primero entender la pieza (por ejemplo, un servidor con `node:http`), después adoptar la herramienta que la simplifica (Express). Así sabrás qué hace la librería por ti y podrás depurarla cuando falle.
</Callout>
