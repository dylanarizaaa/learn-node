## La idea

Un <Term slug="buffer">Buffer</Term> es una secuencia de **bytes**. Archivos, sockets y operaciones criptográficas trabajan con bytes, no con texto; el texto aparece cuando decides **cómo interpretarlos** (la codificación).

```js
const buf = Buffer.from('Piña', 'utf8');
buf;                       // <Buffer 50 69 c3 b1 61>
buf.length;                // 5 bytes…
'Piña'.length;             // …pero 4 caracteres: la «ñ» ocupa 2 bytes en UTF-8
buf.toString('utf8');      // 'Piña'
buf.toString('base64');    // 'UGnDsWE='
buf.toString('hex');       // '5069c3b161'
Buffer.byteLength('€');    // 3
```

`Buffer` es una subclase de `Uint8Array`, así que funciona con APIs web que esperan bytes.

## El problema de los caracteres partidos

Cuando lees un archivo por trozos (con streams, en la siguiente lección), un trozo puede terminar **a mitad de un carácter**:

```js
const bytes = Buffer.from('Piña');
const first = bytes.subarray(0, 3);  // P, i y el primer byte de «ñ»
const second = bytes.subarray(3);    // el segundo byte de «ñ» y la a

first.toString() + second.toString(); // 'Pi��a'  ← carácter roto
```

`StringDecoder` resuelve esto: guarda los bytes incompletos hasta que llega el resto.

```js
import { StringDecoder } from 'node:string_decoder';

const decoder = new StringDecoder('utf8');
decoder.write(first) + decoder.write(second) + decoder.end(); // 'Piña'
```

## Errores comunes

- Usar `string.length` para límites de tamaño en bytes (cabeceras, cuerpos de petición): usa `Buffer.byteLength`.
- Convertir cada trozo de un stream con `toString()` por separado: rompe caracteres multibyte. Usa `StringDecoder` o `stream.setEncoding('utf8')`.
- `new Buffer(...)`: está obsoleto e inseguro. Usa `Buffer.from` o `Buffer.alloc`.
