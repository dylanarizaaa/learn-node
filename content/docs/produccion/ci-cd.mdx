## La idea

La <Term slug="ci-cd">integración continua</Term> (CI) ejecuta automáticamente las comprobaciones en cada *push* y en cada *pull request*: nada entra en la rama principal sin pasar los tests. El **despliegue continuo** (CD) da el siguiente paso: si todo pasa en `main`, construye y despliega.

## Ideas clave

- **`npm ci`**, no `npm install`: respeta el lockfile al pie de la letra y falla si no coincide con `package.json`.
- **Matriz de versiones**: si declaras `"engines": { "node": ">=22.18" }`, prueba en todas las LTS que soportas.
- **Caché de npm** (`cache: npm` en `setup-node`): las instalaciones pasan de minutos a segundos.
- **Rápido primero**: tipos y tests antes que la imagen Docker; si fallan, no gastes tiempo en lo demás.
- **Rama protegida**: en la configuración del repositorio, exige que la CI pase antes de fusionar.

## Mantener las dependencias al día

Dependabot (o Renovate) abre *pull requests* con las actualizaciones; tu CI las prueba. Actualizar poco y a menudo es mucho más fácil que saltar tres versiones mayores de golpe.

```yaml title=".github/dependabot.yml"
version: 2
updates:
  - package-ecosystem: npm
    directory: /
    schedule:
      interval: weekly
    groups:
      dependencias:
        update-types: [minor, patch]
```

## Errores comunes

- Tests que dependen de tu máquina (rutas absolutas, una base de datos local, la zona horaria): en CI fallan. Los de Monedero usan SQLite en memoria y fechas fijas.
- Secretos en el workflow: usa los *secrets* del repositorio (`${{ secrets.NOMBRE }}`), que GitHub oculta en los logs.
- Ignorar una CI en rojo «porque es un test inestable»: arréglalo o elimínalo; una CI en la que nadie confía no protege nada.

## Aplícalo al proyecto

<ProjectStep files={['.github/workflows/ci.yml']}>

Crea el workflow. En tu repositorio de Monedero (donde el proyecto está en la raíz), sería así:

```yaml title=".github/workflows/ci.yml"
name: CI

on:
  push:
    branches: [main]
  pull_request:

jobs:
  test:
    name: Tests (Node ${{ matrix.node }})
    runs-on: ubuntu-latest
    strategy:
      matrix:
        node: [22, 24, 26]
    steps:
      - uses: actions/checkout@v5
      - uses: actions/setup-node@v5
        with:
          node-version: ${{ matrix.node }}
          cache: npm
      - run: npm ci
      - run: npm run typecheck
      - run: npm test
      - run: npm run audit:prod

  docker:
    name: Imagen Docker
    needs: test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - run: docker build -t monedero .
```

El repositorio de esta guía usa un workflow equivalente (con `working-directory: proyecto`) que además valida y compila la documentación. Para el **despliegue**, añade un job con `if: github.ref == 'refs/heads/main'` que publique la imagen en un registro (GitHub Container Registry, por ejemplo) y avise a tu plataforma; cada proveedor tiene su acción o su webhook.
