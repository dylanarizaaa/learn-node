## La idea

**Nunca guardes contraseñas**, ni en texto plano ni cifradas (lo cifrado se puede descifrar). Guarda un <Term slug="hash">hash</Term>: el resultado de una función de un solo sentido. Al iniciar sesión, calculas el hash de lo que escribe la persona y lo comparas con el guardado.

Pero no vale cualquier hash. SHA-256 está diseñado para ser **rápido**, y eso es justo lo que no quieres: si alguien roba tu base de datos, puede probar miles de millones de contraseñas por segundo. Las funciones para contraseñas son **lentas a propósito** y usan mucha memoria: **argon2id**, **scrypt** o **bcrypt**.

## La sal

Si dos personas usan `123456`, sus hashes serían idénticos y un atacante usaría tablas precalculadas. La <Term slug="sal">sal</Term> es un valor aleatorio distinto por usuario que se mezcla con la contraseña: mismo texto, hashes distintos. No es secreta: se guarda junto al hash.

## scrypt en Node

`node:crypto` incluye scrypt, una de las opciones recomendadas por OWASP, sin instalar nada. Sus parámetros controlan el coste: `N` (CPU y memoria), `r` (tamaño de bloque) y `p` (paralelismo). OWASP recomienda como mínimo `N = 2^17, r = 8, p = 1`, que usa unos 128 MiB y tarda del orden de unos cientos de milisegundos.

```js
import { randomBytes, scrypt } from 'node:crypto';
import { promisify } from 'node:util';

const scryptAsync = promisify(scrypt);
const salt = randomBytes(16);
const hash = await scryptAsync('mi-contraseña', salt, 64, { N: 2 ** 17, r: 8, p: 1, maxmem: 256 * 1024 * 1024 });
```

La versión asíncrona se ejecuta en el pool de hilos de libuv: el event loop sigue libre mientras calcula.

## Comparar sin filtrar información

`hashA === hashB` se detiene en el primer byte distinto: midiendo tiempos, un atacante podría deducir cuántos bytes acierta. `crypto.timingSafeEqual` compara en **tiempo constante**.

## Errores comunes

- Usar `md5`, `sha1` o `sha256` para contraseñas.
- Una sal fija para todos (o ninguna).
- Limitar la contraseña a 8–16 caracteres o prohibir símbolos: deja que usen frases largas (pon un máximo razonable, como 128, para no recibir megabytes).
- Usar `scryptSync` en un servidor: bloquea el event loop cientos de milisegundos por cada login.
