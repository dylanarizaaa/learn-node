## La idea

Una operación lenta (leer un archivo, una petición de red) no devuelve el resultado: **recibe una función** a la que Node llamará cuando termine. Esa función es el <Term slug="callback">callback</Term>.

En Node, los callbacks siguen la convención **error-first**: el primer argumento es el error (o `null` si todo fue bien) y los siguientes, el resultado.

```js title="leer.js"
import { readFile } from 'node:fs';

readFile('saludo.txt', 'utf8', (error, text) => {
  if (error) {
    console.error('No se pudo leer:', error.message);
    return;
  }
  console.log('Contenido:', text);
});

console.log('Pedido enviado');
```

```console
$ echo "hola" > saludo.txt && node leer.js
Pedido enviado
Contenido: hola
```

**«Pedido enviado» sale primero.** `readFile` solo *encarga* la lectura y vuelve de inmediato; el callback se ejecuta después, cuando el event loop recibe el resultado.

## El problema: anidar

Cuando una operación depende de otra, los callbacks se anidan, y cada nivel repite el manejo de errores. Es el famoso *callback hell*:

```js
readFile('a.txt', 'utf8', (err, a) => {
  if (err) return console.error(err);
  readFile('b.txt', 'utf8', (err, b) => {
    if (err) return console.error(err);
    writeFile('c.txt', a + b, (err) => {
      if (err) return console.error(err);
      console.log('Listo');
    });
  });
});
```

Las [promesas](/docs/javascript/promesas) y [async/await](/docs/javascript/async-await) resuelven esto. Hoy casi todas las APIs de Node tienen versión con promesas, pero seguirás viendo callbacks en eventos, streams y código antiguo.

## Errores comunes

- **Olvidar el `return`** tras manejar el error: el código sigue y usa un resultado `undefined`.
- **Usar `try/catch` alrededor de `readFile(...)`**: no captura nada, porque el error llega más tarde, dentro del callback.
- **Esperar el resultado en la línea siguiente**: el valor solo existe dentro del callback.

## Aplícalo al proyecto

Empieza el hito 2: Monedero guardará los gastos en un archivo JSON. Crea uno de prueba a mano:

```json title="data/gastos.json"
[
  { "id": 1, "amount": 1250, "category": "comida", "description": "Almuerzo", "date": "2026-11-20" },
  { "id": 2, "amount": 800, "category": "transporte", "description": "Taxi", "date": "2026-11-21" }
]
```

Y un script que lo lee con un callback. Es una versión intermedia: en las dos próximas lecciones la reescribirás con promesas y con `async/await`.

```js title="scripts/ver-gastos.js"
import { readFile } from 'node:fs';
import { summarize } from '../src/domain/expenses.js';
import { formatCents } from '../src/lib/money.js';

readFile('data/gastos.json', 'utf8', (error, text) => {
  if (error) {
    console.error(`✖ No se pudo leer el archivo: ${error.message}`);
    process.exitCode = 1;
    return;
  }
  const { count, total } = summarize(JSON.parse(text));
  console.log(`${count} gastos, ${formatCents(total)} en total`);
});
```

```console
$ node scripts/ver-gastos.js
2 gastos, 20,50 US$ en total
```

`process.exitCode = 1` marca que el programa falló sin cortarlo de golpe; lo verás en [process y argumentos](/docs/nucleo/process-y-argumentos).
